# Security policy

## Supported versions

Security fixes, if any, are made only against the current `main` branch. There
is no supported release train or guaranteed response time.

## Reporting a vulnerability

When this repository is published, use GitHub's **private vulnerability
reporting** feature from the repository's Security tab. Do not include secrets,
tokens, private URLs, proof-of-concept exploit details, or personally
identifying information in a public issue.

The maintainer uses Brooklet personally and does not provide a support service.
Reports may receive no response, but good-faith reports will not be dismissed
for that reason. Please allow time for assessment before public disclosure and
keep testing limited to accounts, devices, and services you own or are
authorised to test.

If private vulnerability reporting has not been enabled on the repository, no
confidential reporting channel is currently available; do not disclose a
vulnerability publicly.

## Scope

Brooklet's direct code, release artifacts, and GitHub Actions configuration are
in scope. Third-party Miniflux/Karakeep instances, article publishers, forks,
and user-operated infrastructure are outside that scope.
